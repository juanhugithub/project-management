# D14 政务台账高级极简前端：视觉验收清单

## 验收目的

确认“暖白纸张 + 近黑文字 + 细线网格 + 克制状态色”的改造，既体现高级极简风格，也不损害科技项目台账的可读性、事实口径和办公电脑可用性。自动检查见 `tests/test_d14_frontend_contract.py`；本清单用于浏览器实际验收。

## 统一准备

1. 使用测试数据或脱敏数据，至少包括：有资金勾稽异常的项目、已归档项目、逾期节点、该拨未拨资金，以及一个空列表或空统计状态。
2. 浏览器缩放为 100%，分别使用 1366×768 与 1024×768 视口。
3. 每项记录“通过 / 不通过”、截图文件名、发现时间和复现步骤；不通过项不可用配色或动画掩盖。

## 视觉与信息层级

| 检查项 | 通过标准 |
| --- | --- |
| 全局基调 | 页面为暖白纸张底色、近黑主文字、极细低对比边线；网格纹理和阴影克制，不影响表格和数字阅读。 |
| 顶部导航 | 导航吸顶但不遮挡内容；当前页清晰可辨；各入口文字始终可见，不以图标或悬停提示替代。 |
| 工作台 | 标题、关键指标和风险待办有明确主次；辅助说明可收纳，但项目数、资金、逾期/该拨未拨不能隐藏。 |
| 状态色 | 绿/黄/红只表达正常、提醒、风险；状态除颜色外还有文字或标签。 |
| 表格与表单 | 列标题、金额数字、筛选项和字段错误层级清楚；表格密集时仍能快速纵向扫读。 |
| 动效 | 仅用于切换、聚焦和辅助反馈；不造成闪烁、不延迟主操作、不隐藏业务事实。 |

## 关键业务流程

| 场景 | 必须看到的内容 |
| --- | --- |
| 项目详情 | 首屏同时可见“项目总金额、计划拨付、已拨付、已到账、待拨、资金勾稽”；不得以“已到位”替代上述口径。 |
| 资金异常 | 勾稽异常、该拨未拨和逾期信息紧邻对应数据，有文字解释，不能只靠颜色或 Hover。 |
| 已归档项目 | “已归档 / 仅查看”状态及不能编辑的原因清晰；不显示误导性的可写主操作。 |
| 新增项目 | 主操作醒目；必填字段、字段级错误、取消与保存均能看见。 |
| 导入、备份、更新 | 每项主操作有明确入口；结果、失败原因或下一步提示在完成操作后可见。 |
| 空状态 | 明确说明当前无数据及下一步可执行动作；不得使用会被误解为系统故障的装饰性空白。 |

## 分辨率与键盘验收

### 1366×768

- 工作台首屏的关键指标、两类待办和新增项目操作不被页头遮挡。
- 项目列表中的查询、筛选、导出和新增项目均可直接看见；信息较宽时允许表格容器滚动，但不得裁切页面主操作。
- 打开项目详情、导入弹窗、错误提示和归档状态分别截图。

### 1024×768

- 导航、工作台指标与双栏待办按设计重排，不发生重叠、文字截断或不可达按钮。
- 表格可通过容器横向滚动查看全列，滚动条或其他可见机制可被发现。
- 弹窗完整保留取消、保存/确认和关闭操作；内容区可滚动，页底操作不丢失。

### 键盘

1. 只用 `Tab`、`Shift+Tab`、`Enter` 和 `Esc` 完成：切换工作台/项目总览、进入筛选、打开新增项目、取消弹窗。
2. 每一步都有高对比、连续可见的焦点标记。
3. 错误提示、状态标签和主操作不需要鼠标悬停才能发现。
