# 0001：G1 领域契约（HUMAN 已确认）

**状态：已确认（2026-08-13）**
**适用阶段：G1；G2 及以后实现必须遵守本契约。**

## 决策

1. **资金单记录不拆分。** `funding` 一条记录同时承载计划与实际事实：`amount` 是该笔资金的计划/批准金额，`plan_date` 是应拨日期，`actual_date` 是实际拨付日期，`status` 是拨付/到账状态。G2 不新建“资金计划”与“资金拨付”两类实体，也不猜测出第二个金额。
2. **项目业务唯一键为“项目编号/文号 + 承担企业统一社会信用代码”。** 编号非空、企业信用代码非空时，该组合必须唯一。无项目编号的历史记录不能自动入账或自动合并，进入待 HUMAN 确认队列。
3. **正常状态流转固定为：** `申报中 → 已立项 → 实施中 → 待验收 → 已验收 → 绩效跟踪 → 已完结`。只能相邻前进，禁止回退、跳跃或由终态离开。
4. **中止为不可恢复终态。** 仅允许从 `已立项`、`实施中`、`待验收` 进入；进入后没有任何出边。
5. **撤销为不可恢复终态。** 仅可由人工显式操作进入，不存在自动流转路径；其操作授权、审批和留痕细则列为未来待定事项，**不阻塞本轮 G1/G2**。

## 同时冻结的解释

- 项目必须关联一个存在且未删除的承担企业；不能以删除企业制造无关联项目。
- 金额勾稽基准是项目总金额与各资金记录 `amount` 之和；“计划拨付、已拨付、已到账、待拨、逾期未拨”均由同一笔记录的日期和状态确定，不能混用。
- 实现唯一键时，数据库可使用 `project(project_no, enterprise_id)` 唯一索引；这是对信用代码组合键的等价投影，前提是企业信用代码自身保持唯一且非空。

## 未阻塞的后续事项

- 撤销的操作者角色、二次确认与授权理由字段，在 G3 审计设计时由 HUMAN 决定。
- 无项目编号历史记录的逐条治理，只能依据迁移预检报告由 HUMAN 决定，禁止自动补号或名称匹配。
