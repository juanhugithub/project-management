# G6 安全与权限验收契约

## 目标

将当前单机本地台账升级为有明确操作者、角色和数据范围边界的应用。G6 不改变 G1 至 G4 的项目、资金、归档和导入领域规则，只为它们增加统一的访问控制。

## 固定的外部约定

| 项目 | 约定 |
| --- | --- |
| 登录 | `POST /api/auth/login`，请求体为 `username`、`password`；成功后返回用户摘要并设置 `HttpOnly` 会话 Cookie。 |
| 未登录 | 任何 `/api/*` 业务读写接口均返回 `401`。 |
| 角色 | `admin`、`editor`、`viewer` 三种。 |
| viewer | 仅能读取自己数据范围内的列表、详情与统计。 |
| editor | 可在自身数据范围内维护企业、项目、资金和节点；不能导入、归档、解除归档或恢复。 |
| admin | 可管理用户、数据范围与全部业务；导入确认、归档、解除归档、恢复均只允许 admin。 |
| 数据范围 | 以企业的 `district` 为最小可见范围；项目、资金、节点通过所属企业项目继承该范围。 |
| 审计 | 每一条写操作使用当前已认证用户名写入 `audit_log.operator`，不得使用固定 `local-user`。 |

## G6 验收步骤

1. 先运行 `python -X utf8 -m pytest tests/test_g6_security_contract.py -q`，所有用例应为严格 xfail。
2. 实现身份、会话、角色和数据范围后，逐项移除对应 `xfail`。
3. 运行同一命令，四项用例必须全部通过：未登录拒绝、角色拒绝、审计操作者、列表与统计范围。
4. 最后运行 `python -X utf8 scripts/check.py`；测试不得改变 `data/project.db`。

## 明确不在本阶段的事项

- 不引入多租户、组织层级、细粒度字段脱敏或外部统一身份认证。
- 不改变项目唯一键、资金单记录模型、中止不可恢复规则。
- 不通过前端隐藏或查询参数来代替服务端权限过滤。
